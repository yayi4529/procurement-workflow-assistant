# Skill workflow 飞书验收清单

自动化测试覆盖签名 webhook、AssistantService、BackendClient 和回复卡片构建；真实飞书账号
用于发布前平台验收，不由测试代码主动给生产用户发消息。

## 数据与记录

- 使用隔离前缀 `TEST-SKILL-E2E-*`。
- 四个账号分别绑定需求人、楼长、采购员和仓库管理员角色。
- 每个用例记录飞书消息 ID、trace ID、采购单号、skill、workflow、phase 和最终状态。
- 不在记录中保存 open_id、手机号、银行账号或完整 webhook payload。

## 固定用例

1. 需求人发送“我要买一个开关电源”，确认只生成一个草稿并等待正式卡片。
2. 需求人描述 UPS 多部件故障，再回复“2个风扇、4个电容”，确认续接原 workflow。
3. 采购员发送“今年每月采购金额趋势”，确认只开放 `analyze_procurement`。
4. 采购员请求供应商推荐，确认返回聚合证据、资格与黑名单核验结果。
5. 在候选选择阶段回复“第一个”，确认服务重启后仍续接当前 workflow。
6. 发送“重新开始”，确认旧 workflow 完成/清除，下一条消息建立新状态。
7. 四角色正式提交、审批、采购和入库只操作飞书正式卡片，确认不经过 LLM。

## 发布门槛

- `hybrid` 下结构化路由与旧关键词影子结果差异已记录且可解释。
- 低置信请求只追问一次，未暴露全工具集。
- SQL 校验失败最多修正一次；成功后不重复查询。
- 验收通过后配置切换为 `PROCUREMENT_LLM_SKILL_ROUTING_MODE=strict`。
